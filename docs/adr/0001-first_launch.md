# ADR-0001. Первый запуск арены как пилот AR-12

- Статус: proposed
- Дата: 2026-11-15

## Контекст

Перед основной кампанией нужно оценить, сколько времени занимает подготовка и проверка одного кандидата и сколько токенов расходует исследователь. У AR-12 есть три стартовых решения с разными подходами: `matching`, `boosting` и `transformer`. Для первого запуска можно использовать фиксированную подвыборку исходного train и существующий Docker runner арены.

## Решение

Провести последовательный пилот с предлагаемым лимитом в шесть предложений. Зарегистрировать три бейзлайна и по одному новому варианту от каждого. Неудачные предложения тоже занимают место в лимите.

- Обучать кандидатов на 14 025 примерах. Проверять их через train-оценщик на одних и тех же 256 примерах, по 128 на класс. Зафиксировать разбиение и метрику `ar12-tpr-v3` до начала поиска. Максимизировать TPR при FPR не выше 5%. При превышении порога балл равен нулю.
- Использовать DeepSeek V4.1 Flash для подготовки гипотез и патчей. При вызове через OpenRouter передавать описание задачи и два исходных файла родителя. Проверять патч и обучать одобренный код локально. Запускать оценку кандидата в Docker без сети.
- Записывать в общий журнал родителя, снимок пакета, время подготовки, токены исследователя и длительность оценки. Отмечать неполный учёт токенов. Считать средние затраты по новым вариантам и указывать число наблюдений.
- После поиска сохранить один итоговый вариант по train-score. Разделы `public` и `private` в пилоте пусты.
- Вместо агента проверки будет использован код. Все проверки из промпта `arena/prompts/prepare.md ` можно сделать кодом.

## Альтернативы

- **Сразу запустить основную кампанию с `public` и `private`.** Это даст закрытую оценку финалистов, но потребует подготовить закрытые выборки, настроить изоляцию агентов и утвердить бюджет до первых замеров стоимости итерации.
- **Ограничиться smoke-проверкой и прогонами бейзлайнов.** Этого достаточно для проверки тракта оценки. Данные о подготовке, ревью и обучении новых вариантов придётся собирать отдельно.

## Последствия

- Пилот даст до трёх наблюдений для оценки порядка затрат на одну исследовательскую итерацию. Количество доступных замеров указывается в отчёте.
- На 128 безопасных примерах один ложный блок меняет FPR примерно на 0,78 процентного пункта. Итог пилота опирается на фиксированную train-подвыборку, а качество на закрытых данных остаётся предметом основной кампании.
- Docker изолирует код кандидата во время оценки. Обучение и работа локального исполнителя идут на хосте. Для основной кампании потребуется проверить изоляцию агентов и обучения от закрытых данных.
- Результаты подготовки и smoke-проверок уже зафиксированы. Статус ADR остаётся `proposed` до утверждения пилотного бюджета.
