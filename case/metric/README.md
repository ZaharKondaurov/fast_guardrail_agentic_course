# Метрики AR-12

Основной пакет AR-12 описан в `metric.json` рядом с этим файлом. Arena загружает один пакет за прогон. Команда `--collect` получает `example` и `answer`, а команда `--aggregate` получает `results` всего раздела.

Итоговый `score` равен TPR при FPR ≤ 5 %, p99 ≤ 5 мс и достаточной пропускной способности. При нарушении любого порога или при невалидном ответе балл равен 0. Arena ранжирует кандидатов по `direction: maximize`. Диагностические значения агрегатор возвращает в `statistics`.

Последний аргумент `aggregation.argv` в `metric.json` задаёт минимум сообщений в секунду. Черновое значение — 1 000 сообщений/с. Перед кампанией утвердите порог на выбранном CPU и зафиксируйте его в пакете. Для заморозки подготовьте чистый каталог с `metric.json` и `score.py`.

Отдельные диагностические пакеты:

- `tpr/` — основная метрика. Возвращает TPR, если FPR ≤ 5 %, иначе 0. Для расчёта нужны оба класса.
- `fpr/` — доля блокировок среди безопасных сообщений.
- `p99/` — 99-й процентиль времени классификации в миллисекундах. Граница AR-12 — 5 мс.
- `throughput/` — число сообщений, делённое на суммарное время их классификации. Минимум задаётся до кампании.

Классы кодируются как `0` (пропустить) и `1` (заблокировать). В датасете и локальном оценщике это целые числа. Контракт арены требует строковые `reference` и `answer`, поэтому на этой границе передаются `"0"` и `"1"`.

Для расчёта p99 и пропускной способности операторский адаптер должен добавить замер прогретого фильтра на каждом сообщении в `results[*].resources.solver.inference_ns`. Штатный runner передаёт `wall_seconds` с накладными расходами запуска.

Общий оценщик `python -m case.ways.baseline.evaluate` использует те же формулы из `score.py`. Чтобы применить локально тот же порог пропускной способности, передайте `--min-messages-per-second` со значением из пакета. AUC кривой кампании рассчитывается по журналу арены.

```bash
uv run pytest case/metric/tests
```
